# 15. Paritas dengan SION

Catatan kerja untuk menyamakan logika bisnis newsekolah dengan SION, aplikasi asal yang kodenya ada di `reference/sion-rebuild-go`. Dokumen ini menjawab satu pertanyaan: sampai mana pekerjaan ini, dan apa yang tersisa. Perbarui setiap kali ada bagian yang selesai.

Posisi terakhir: 19 November 2026 (audit langsung dan tiga putaran perbaikan UI web, lihat [pembaruan 19 November, audit langsung](#pembaruan-19-november-lanjutan-audit-langsung-dan-tiga-putaran-perbaikan); sebelumnya penyempurnaan UI web setelah overhaul, lihat [pembaruan 19 November](#pembaruan-19-november-penyempurnaan-ui-web-setelah-overhaul); sebelumnya, 18 November: overhaul UI web: tinjauan visual akhir, dua putaran perbaikan, dan perbaikan sesi sudah digabung di cabang `claude/ui-overhaul-penyempurnaan-893ed6`, yang ada di GitHub tetapi belum digabung ke `main`; fase tes akhir sedang berjalan; lihat [pembaruan 18 November](#pembaruan-18-november-overhaul-ui-web-tinjauan-akhir-dua-putaran-perbaikan-dan-fase-tes)). Di luar paritas: pemilik produk meminta tampilan web yang sangat profesional dengan sedikit animasi, dengan identitas Hijau Segar dipertahankan. Dasarnya audit [13 November](analysis/ui-overhaul-audit-2026-11-13.md) (994 tangkapan layar untuk sepuluh peran, 115 layar dinilai: 73 perlu dipoles dan 42 perlu dirancang ulang, 382 temuan terverifikasi), dan keputusannya dicatat di [spesifikasi overhaul](superpowers/specs/2026-11-14-ui-overhaul-design.md), yang membagi pekerjaan menjadi enam gelombang. **Gelombang 1 (fondasi) selesai**: token peran (permukaan, batas kontrol berkontras 3:1, lapisan keadaan, elevasi, warna semantik), delapan peran tipografi yang dipakai semua komponen `packages/ui`, sistem gerak (80 sampai 320 ms, hanya `opacity`/`transform`, mati di `prefers-reduced-motion`), aturan lint baru (warna di luar token dilarang di seluruh repo, ukuran font literal dilarang di `packages/ui`), dan perbaikan cacat primitif (Button saat memuat, fokus dan `aria-sort` di DataTable, Checkbox indeterminate, urutan z-index, aksen mode gelap, TabsList yang tidak lagi melebarkan halaman). Bersamaan dengan itu digabung delapan kontrol form baru (`Calendar`, `DatePicker`, `DateRangePicker`, `MonthPicker`, `TimePicker`, `NumberInput`, `RadioGroup`, `SegmentedControl`) dan sekitar seratus perbaikan cacat fungsional dari audit di lima area (antara lain meja sirkulasi yang bisa dimulai dengan memindai kartu, QR kios kunjungan yang memperbarui diri, tanggal dan "hari ini" di zona waktu sekolah, pratinjau kop laporan yang tadinya diblokir CSP, konfirmasi sebelum aksi tamu dan pengembalian terlambat, serta panel tab yang sah untuk tab yang dipakai sebagai navigasi). Diverifikasi di cabang gabungan (`7816f2a5`): `pnpm typecheck` dan `pnpm lint` lulus di 14 paket tanpa error, uji web 266 berkas dan 1.334 uji lulus, uji `packages/ui` 37 berkas dan 225 uji lulus, uji kontras token 250 pasang lolos AA. Belum diverifikasi: suite e2e (smoke dan simulasi) belum dijalankan, dan Storybook belum dibangun di CI. Tiga uji paginasi web (`members-view`, `bills-list-view.paging`, `copies-browser-view.paging`) bisa kena batas 5 detik bila mesin sedang dibebani; sendirian semuanya lulus. Angka dasar yang dipakai mengukur kemajuan gelombang berikutnya (dari audit, di `apps/web`): 1.608 ukuran font literal, 155 kartu buatan tangan, 145 judul tanpa `font-heading`, 496 label form tulis tangan, 188 pemakaian token `status-*` sebagai warna semantik. Tersisa: gelombang 2 (primitif bersama, sedang dikerjakan), 3 (kerangka halaman dan shell), 4 (codemod penyeragaman), 5 (desain ulang layar utama per area), dan 6 (potret ulang, tinjauan akhir, pembaruan `docs/05` dan `docs/07`). Di luar cakupan dan menunggu keputusan pemilik produk: sekitar 13 temuan yang butuh perubahan API (misalnya monitor untuk pengguna yang sudah login, target kenaikan kelas yang memilih kelas pertama per tingkat), serta izin peran yang tampak janggal di data seed (satpam bisa membuka loket pembayaran, kepala sekolah ditolak di `/monitor`; guru yang ditolak di `/supervision/my-report` sudah diputuskan dan diperbaiki, lihat [pembaruan 19 November, supervisi guru](#pembaruan-19-november-lanjutan-supervisi-milik-guru)). Sudah selesai dari daftar itu: `GET /v1/late-arrivals/current` kini menjawab 204 No Content (bukan 404) saat tidak ada keterlambatan yang sedang berjalan, sehingga peramban tidak lagi mencatat permintaan gagal di setiap pemuatan halaman keterlambatan; web (`features/permits/api.ts`) dan mobile (`useCurrentLateArrival` di `apps/mobile/src/lib/api/hooks/permits.ts`) memetakan badan kosong itu ke `null`. Hanya build mobile yang sudah memuat hook baru ini yang menangani 204: build lama yang sudah terpasang hanya mengenali 404, jadi untuk 204 ia menerima `undefined`, yang ditolak TanStack Query sebagai data tidak sah sehingga kartu keterlambatan tampil dalam keadaan error sampai aplikasi diperbarui.

Posisi sebelumnya: 25 September 2026 (dua item ledger perpustakaan: barcode kartu anggota, cetak kartu massal). **Barcode gambar pada kartu anggota**: `library/service/print.go`'s `PrintMemberCard` sebelumnya lewat `documents.Renderer` (perender HTML->PDF berbasis teks polos, membuang tag `<img>` -- lihat komentar paket) sehingga nomor anggota cuma tercetak sebagai teks; sekarang merender langsung dengan `fpdf`, memakai layout kartu ATM 85,6x54mm (`domain/cards.go`'s `CardPosition`, 2 kolom x 5 baris per A4, dari aplikasi lama `library_cards.go`) dan Code 128 gambar nomor anggota lewat `generateCode128PNG` yang sama dipakai label eksemplar (`service/labels.go`) -- satu jalur kode barcode untuk keduanya. Surat keterangan bebas pustaka tidak disentuh (tetap lewat `documents.Renderer`, tidak butuh barcode). **Cetak kartu anggota massal**: endpoint baru `POST /v1/library/members/cards` (`printLibraryMemberCards`, permission `manage_library_members`, `openapi/modules/library.yaml`) mencetak sampai 500 kartu (`domain.CardMaxPerPrint`) dalam satu PDF, dipilih lewat tepat satu dari tiga mode -- daftar `member_ids` eksplisit (urutan dipertahankan, query `GetMembersByIDs` baru), `member_type_id`, dan/atau `class_id` (keanggotaan aktif lewat `enrollments`, query `ListMembersForCardPrint` baru, keduanya bisa digabung). Layar Anggota (`members-view.tsx`) mendapat kolom pilihan baris (`selectionColumn`, pola sama `copies-browser-view.tsx`) plus bilah cetak `MemberCardPrintBar` untuk baris terpilih, dan tombol "cetak sesuai filter jenis" saat filter jenis anggota aktif. Diuji integrasi Postgres asli (`member_cards_integration_test.go`): tiga mode seleksi, gabungan tipe+kelas, penolakan kombinasi tidak sah (tanpa seleksi, id dicampur filter, id melebihi 500), filter tanpa hasil (404), dan paginasi lewat 10 kartu per halaman; test kedua membuktikan barcode sungguhan tertanam (marker `/Subtype /Image` pada PDF, bukan lagi kartu berbasis teks murni). Tidak ada migrasi (query baru memakai tabel `library_members`/`enrollments` yang sudah ada). `go test ./...` penuh (real Postgres via testcontainers), `pnpm typecheck && pnpm lint && pnpm test`, dan `check-migrations.sh` lulus.

Sesi paralel 25 September 2026 (sesi backend: laporan PDF izin keluar, heartbeat presence, publish realtime dari worker). Menutup dua baris "Pekerjaan yang ditunda" di bawah plus satu item tambahan yang ditemukan selama kerja. **Laporan PDF izin keluar**: ternyata sudah selesai dari migrasi pusat laporan generik sebelumnya (`reports/service.RunDocument` + `reportdoc`) -- baris tabel di bawah cuma belum diperbarui. Ditambah bukti ujung-ke-ujung baru: `TestExportReportExitPermitYearlyPDFHasLetterhead` (`apps/api/internal/wiring/reports_integration_test.go`, Postgres asli lewat `dbtest`) memanggil `RunDocument` yang sama dipakai endpoint `GET /v1/reports/{reportKind}/export`, dengan kop laporan tenant sungguhan tersimpan lewat `school.Service.UpdateReportHeader`, memverifikasi kop muncul di sel A1 XLSX dan keluaran PDF valid. **Heartbeat presence**: `apps/api/cmd/api/ws.go`'s `wsMeHandler` kini menjalankan `heartbeatPresence` (goroutine baru, tiap 30 detik lewat `presenceHeartbeatInterval`) selama koneksi `/ws/me` hidup, bukan cuma sekali saat connect; berhenti bersih lewat `client.Done()` saat socket ditutup. Kedaluwarsa sisi server (`realtime.Presence.Snapshot`'s filter ttl, plus `RedisPresenceStore`'s trim per replika) sudah ada sebelumnya -- ditambah `presence_test.go` dan `ws_test.go` (websocket sungguhan lewat `httptest`) yang mengujinya.

Sesi yang sama, item tambahan: **Publish realtime dari worker** (ditemukan saat menyelidiki cara kerja presence/hub, bukan bagian dari dua baris tabel "Pekerjaan yang ditunda"): `cmd/worker/main.go` (proses `WORKER_INLINE=false`) tidak pernah membangun `realtime.Hub` sama sekali, jadi notifikasi yang dibuat job latar belakang (pengingat jatuh tempo perpustakaan, laporan terjadwal siap, dan job lain manapun yang memanggil `notifications` service's realtime publish) tersimpan di inbox tapi tidak pernah didorong ke klien `/ws/me` yang tersambung sampai halaman dimuat ulang. Diperbaiki dengan hub publish-only di worker (`realtime.NewHub` memakai broadcaster Redis yang sama `cmd/api` pakai, tanpa `mountRealtimeRoutes`/`Upgrade` -- worker tidak pernah melayani websocket, jadi `hub.Subscribe` tak pernah dipanggil di sana, degradasi ke no-op tanpa Redis), disuntik ke `notifications.Dependencies.Realtime`, `permits.Dependencies.Hub`, dan `attendance.Dependencies.Hub`. Sambil di situ, ditemukan dan diperbaiki bug lebih dalam: `notifications/service.RealtimePublisher.Publish` sebelumnya membaca tenant dari `httpx.TenantIDFromContext(ctx)`, yang HANYA terisi untuk request HTTP -- job River (baik di worker terpisah maupun mode inline `cmd/api`) tidak pernah membawa nilai itu di context-nya, jadi push realtime dari alur job (pengingat jatuh tempo, dll) senyap gagal bahkan sebelum perbaikan hub ini, di KEDUA mode deployment. Diperbaiki dengan mengubah signature `RealtimePublisher.Publish` supaya menerima `tenantID` eksplisit dari pemanggil (`notify.go`'s `notifyOne` sudah punya `tenantID` di parameternya) alih-alih dari context. Diuji: `TestPublishOnlyHubReachesSubscriberOnSeparateHub` (`internal/platform/realtime/hub_test.go`, broadcaster palsu di proses -- repo belum punya dependensi testcontainers-Redis atau miniredis) membuktikan publish dari hub tanpa subscriber lokal (meniru worker) sampai ke klien websocket sungguhan di hub terpisah (meniru `cmd/api`) lewat broadcaster bersama. Semua perubahan diverifikasi: `go build`/`go vet`/`go test ./...` (Postgres asli lewat testcontainers) dan `pnpm typecheck && pnpm lint && pnpm test` lulus; tidak ada migrasi baru.

Sesi paralel 25 September 2026 (sesi provisioning tenant baru: role/duty/library member type hilang untuk tenant hasil `cmd/bootstrap`). Bug produksi terverifikasi di database live: satu-satunya tenant (dibuat lewat `cmd/bootstrap`) cuma punya dua peran, `super_admin` (dari bootstrap) dan `principal` (backfill migrasi 0117), dan nol jenis tugas tambahan -- admin tidak bisa memberi siapa pun peran guru/siswa/orang tua/pegawai/pustakawan/admin, dan tugas wali kelas/BK/piket/wakil kepala sekolah/satpam/pustakawan tidak ada. Sebabnya: `cmd/bootstrap` cuma pernah membuat peran `super_admin`; provisioning penuh (setiap peran sistem dari `authz.RoleDefaults` beserta izinnya, dan jenis tugas baku dari `authz.DutyTypeDefaults`) hanya terjadi lewat jalur `platform.CreateTenant` (konsol SaaS) dan `cmd/seed`; `syncSystemRoleDefaults` di `internal/platform/migrator/migrator.go` yang jalan tiap `cmd/migrate` cuma MENAMBAH izin ke peran sistem yang SUDAH ADA, tidak pernah membuat peran atau jenis tugas yang hilang -- makanya peran `principal` harus ditambal lewat migrasi khusus 0117 saat diperkenalkan, pola yang tidak bisa diulang tiap kali ada peran baru. Diperbaiki dengan satu rutin idempoten add-only baru, `migrator.EnsureTenantDefaults` (`internal/platform/migrator/tenant_defaults.go`): untuk satu tenant, membuat tiap peran sistem dari `RoleDefaults()` yang belum ada (dengan izin default penuhnya, `is_system=true`) kecuali `super_admin` (sengaja tidak pernah dibuat otomatis -- ia membawa `platform_superadmin`, gerbang konsol lintas-tenant, dan tenant hasil `CreateTenant` multi-tenant tidak boleh pernah mendapatkannya begitu saja), tiap jenis tugas baku dari `DutyTypeDefaults()` yang belum ada, dan (temuan audit tambahan, lihat di bawah) tiap jenis anggota perpustakaan baku dari `librarydomain.MemberTypeDefaults()` yang belum ada -- peran/tugas/jenis anggota yang SUDAH ADA (sistem atau kustom, nama baku atau sudah diganti, izin baku atau sudah disunting admin) tidak pernah disentuh sama sekali. Dipanggil dari `cmd/migrate`'s `PostUp` untuk tiap tenant (sebelum `syncSystemRoleDefaults` yang perilakunya persis dipertahankan), dan dari `cmd/bootstrap` tepat di dalam transaksi tenant yang sudah ada (lewat pemakaian ulang transaksi ambien `database.WithTenantTx`) supaya instalasi baru langsung lengkap tanpa menunggu `migrate` berikutnya. Konsol platform's `CreateTenant` disatukan ke rutin yang sama (`IdentityProvisioner.SeedDefaultDuties` diganti `EnsureTenantDefaults`, diimplementasikan di `internal/wiring/platform.go` supaya modul platform sendiri tidak perlu mengimpor `platform/migrator` yang di luar tabel dependensi lapisan modul) -- sekalian menemukan `CreateTenant` pun SELAMA INI cuma pernah membuat peran `admin`, bukan guru/siswa/orang tua/pegawai/pustakawan/kepala sekolah juga, bug yang sama persis di jalur SaaS. Audit item 3 (hal lain yang disediakan `CreateTenant`/`cmd/seed` untuk tenant baru tapi dilewati bootstrap): `tenant_settings` aman dilewati (setiap pembacaan sudah defensif, fallback ke nilai baku Go bila baris tidak ada); definisi alur kerja izin keluar/leave request (`workflow_definitions`) aman dilewati (`permits/service.EnsureDefaultDefinitions` sudah menyediakan lazy-seed saat permintaan pertama, disebut eksplisit di komentar migrasi 0040 sebagai desain yang disengaja); templat notifikasi tidak relevan (tidak ada tabelnya -- isi notifikasi adalah string Go baku yang dikompilasi ke binary, `notifications/service/events.go`'s `eventMappings`); jenis anggota perpustakaan (`library_member_types`) TERNYATA wajib -- perpustakaan aktif baku untuk tiap tenant (`feature_flags` opt-out) dan semua jalur registrasi anggota (manual/massal/otomatis saat pinjam pertama) mensyaratkan baris jenis anggota yang sudah ada, jadi ditambahkan ke rutin di atas; dua jenis baku (Siswa, Guru & Staf) dipindah dari duplikasi lokal `cmd/seed` ke `librarydomain.MemberTypeDefaults`, sumber tunggal baru untuk keduanya. Test (Postgres asli lewat `dbtest`/testcontainers): tenant yang dibuat persis seperti `cmd/bootstrap` (tenant + `super_admin` saja) mendapat semua peran sistem berikut izin defaultnya dan semua jenis tugas baku setelah `EnsureTenantDefaults` jalan; jalan dua kali tidak mengubah apa pun; peran kustom, peran sistem yang sudah diganti nama plus dicabut satu izin defaultnya, jenis tugas yang diganti nama plus dicabut satu izin defaultnya, dan jenis anggota perpustakaan yang diganti nama semuanya selamat utuh; lewat `migrator.PostUp` penuh, izin default yang dicabut dari peran yang sudah ada tetap direstorasi (perilaku `syncSystemRoleDefaults` yang memang dipertahankan sengaja, bukan bug) sementara izin ekstra di luar default dan peran kustom tidak disentuh; dan test ujung-ke-ujung `cmd/bootstrap` sendiri (memanggil `run()` yang tidak diekspor langsung dari test di package yang sama, DATABASE_URL diarahkan ke koneksi `app_rw` terbatas RLS milik container test) membuktikan lewat binary sungguhan. Verifikasi: `go build`/`go vet`/`go test ./... -count=1` (Postgres asli via testcontainers) lulus semua, `bash infra/scripts/check-migrations.sh` lulus (tidak ada migrasi baru -- perbaikannya murni kode Go, bukan skema).

Sesi paralel 25 September 2026 (sesi audit operasi OpenAPI tak terjangkau web). Baris "46 operasi belum terjangkau" di ringkasan di bawah berasal dari hitungan grep dangkal (`.GET("path"`/`.POST("path"` literal saja) yang tidak menghitung endpoint ekspor biner yang dipanggil lewat `fetch` mentah dengan path dinamis (`` `${API_URL}/v1/.../${id}/export` ``) -- pola yang dipakai hampir semua unduhan XLSX/PDF di `apps/web` karena `openapi-fetch` selalu mem-parse respons sebagai JSON. Menghitung ulang dengan mencocokkan operationId x path x method satu per satu terhadap kode web (termasuk pola `fetch` dinamis itu, dan membedakan method yang berbagi path yang sama, mis. `POST`/`PUT`/`GET` semuanya di `/v1/grading/grade-ranges`) menemukan hanya 20 operasi API yang betul-betul tidak dipanggil kode web, bukan 46. Sembilan di antaranya di luar cakupan sesi ini dan dijelaskan satu per satu di bawah (websocket/presence, webhook WhatsApp, kesehatan server dan refresh token internal, definisi peran, kartu/cetak anggota perpustakaan). Sebelas sisanya genuinely unreachable dari web; sembilan dari sebelas itu ternyata sudah punya jalan pintas fungsional yang setara (endpoint massal/bulk yang sudah dipakai UI mencakup kasus satu-item, atau field yang datanya sudah identik dengan yang dikembalikan endpoint daftar) sehingga nilainya bagi sekolah mendekati nol -- dijelaskan satu per satu, tidak dibuatkan layar semu hanya demi kelengkapan. Dua sisanya nilainya nyata dan dikerjakan sesi ini: **Nonaktifkan penugasan mengajar** (`PUT /v1/academic/teaching-assignments/{assignmentId}`, `updateTeachingAssignment`) -- tab "Guru pengampu" di detail kelas (`apps/web/features/school/components/teaching-panel.tsx`) sebelumnya hanya punya hapus permanen (`Trash2`) untuk penugasan mengajar; kini ada aksi nonaktifkan (`Ban`) di samping hapus, plus bagian "Tampilkan penugasan nonaktif" yang bisa diaktifkan kembali (`RotateCcw`) -- riwayat penugasan (dipakai jurnal, presensi, nilai) tidak lagi hilang hanya karena guru cuti atau kelasnya direshuffle. **Catatan jadwal saat diubah** (`GET /v1/schedules/{scheduleId}`, `getSchedule`) -- form ubah blok jadwal (`schedule-form.tsx`) sebelumnya hanya punya `ScheduleBlock` (bentuk baris gabungan yang dipakai kisi jadwal), yang tidak membawa field `notes`/`mutation_policy`; menyimpan perubahan jadwal diam-diam menghapus catatan yang sudah ada karena form tidak pernah tahu catatan itu ada. Form kini memuat detail penuh sekali saat dialog ubah dibuka lewat `useScheduleQuery` baru, menampilkan field catatan terisi, dan menonaktifkan tombol Simpan (dengan pesan "Coba lagi") selama pemuatan gagal supaya catatan lama tidak pernah tertimpa tanpa sengaja. Kedua fitur diuji lewat interaksi (klik nonaktifkan/aktifkan lagi, dan pemuatan/error/pengisian catatan) mengikuti pola test komponen yang sudah ada; tidak ada perubahan API atau migrasi. Rincian daftar lengkap 20 operasi, alasan tiap pengecualian, dan peringkat nilai kesembilan operasi yang tidak dikerjakan ada di [Lampiran F](analysis/openapi-web-gaps-2026-09-25.md).

Sesi paralel 25 September 2026 (sesi izin lihat-nilai untuk Kepala Sekolah). Modul penilaian tadinya cuma punya satu izin `manage_grades` yang menggerbangi baca maupun tulis, jadi peran `principal` (Kepala Sekolah, migrasi 0117) tidak bisa melihat nilai sama sekali (celah yang sudah dicatat eksplisit di komentar `role_defaults.go`). Menutup celah itu: permission baru `view_grades` (`internal/platform/authz/permissions.go`, grup "grading") ditambahkan ke setiap peran yang sudah punya `manage_grades` (jadi `manage_grades` selalu menyiratkan `view_grades` -- tidak ada peran yang kehilangan akses baca) dan ke peran `principal`; migrasi `0118_grading_view_grades_permission` membackfill kedua hal itu untuk tenant yang sudah ada (idempoten -- baris `permissions` disisipkan dulu sebelum `role_permissions` mereferensikannya, karena `cmd/migrate`'s PostUp yang biasanya meng-upsert katalog izin baru jalan setelah migrasi SQL, bukan sebelum). Operasi baca-saja grading (`getGradebook`, `exportGradebook`, `listGradeRanges`, `listTPMappings`, `previewEraporExport`, `exportErapor`, `exportEraporLegacy`, plus laporan katalog `grading.report_scores` di modul reports) pindah `x-permission`-nya dari `manage_grades` ke `view_grades`; operasi tulis (simpan skor, komponen, publikasi, grade ranges, TP mapping) tetap `manage_grades`. Tidak ada mekanisme "salah satu dari" permission di level OpenAPI (`authz.Authorize` mengecek tepat satu `x-permission` per operasi) -- kepala sekolah membaca sekolah penuh lewat pola yang sudah ada di modul attendance: `GradingHandler.canViewAny` (baru, `transport/http/handler.go`) mem-bypass pemeriksaan `requireTeaches` di service layer untuk pemegang `view_reports` (izin pengawasan yang sudah dimiliki principal tapi TIDAK dimiliki guru biasa) atau `manage_master_data`, persis seperti `attendance.Actor.CanViewAll` memakai `view_reports` -- sehingga guru yang kebagian `view_grades` lewat implikasi `manage_grades` TIDAK ikut mendapat bypass sekolah-penuh (skop mereka tetap kelas sendiri lewat `requireTeaches`). Web: `lib/navigation.ts`'s entri "grading" pindah dari `permission: "manage_grades"` ke `anyPermission: ["manage_grades", "view_grades"]` (pola yang sama dipakai leave-requests/exit-permits); `grading-view.tsx` menambah `canViewGrades`/`canOpenAny` (kini `manage_master_data || view_reports`, mencerminkan `canViewAny` backend) sehingga kepala sekolah melihat pemilih kelas/mapel sekolah-penuh dan tab e-Rapor, tanpa tab TP-mapping/pengaturan; `GradebookSheet` sudah lama menerima prop `canManage` yang menyembunyikan semua kontrol edit/simpan/terbitkan, jadi cukup dialiri `canManageGrades` (tetap `false` untuk pemegang `view_grades` saja) tanpa perubahan di dalam `gradebook-sheet.tsx`/`gradebook-table.tsx`. ## Bagaimana pekerjaan ini berjalan

1. **Perbandingan.** Tiap aturan bisnis di handler SION dicari padanannya di kode baru dan diberi status per fitur. Hasil lengkapnya ada di [Lampiran D](analysis/parity-sion-before.md). Dari 72 fitur, saat itu 18 lebih baik, 2 sama, 39 sebagian, dan 13 hilang. Sebelas dari yang hilang ada di perpustakaan.
2. **Perbaikan per modul.** Delapan pengerjaan paralel menutup celah di identitas, akademik, presensi, perizinan, kesiswaan, penilaian, notifikasi, dan perpustakaan.
3. **Review.** Lima review independen memeriksa ulang klaim setiap perbaikan terhadap kode, bukan terhadap pesan commit. Review menemukan 27 masalah baru atau klaim yang tidak sepenuhnya benar.
4. **Verifikasi dengan database.** Seluruh pengerjaan sebelumnya hanya menjalankan test dengan `-short`, sehingga tidak satu pun test integrasi pernah dieksekusi. Menjalankan migrasi, seed, dan test penuh terhadap Postgres menemukan masalah yang tidak tertangkap test unit, termasuk seed yang gagal total dan bug SQL laten pada penyimpanan nilai rapor.
5. **Perbaikan temuan review**, lalu layar presensi disambungkan ke API baru.
6. **Pembangunan layar** untuk kemampuan backend yang belum punya antarmuka, dalam tiga kelompok paralel: perpustakaan, kesiswaan bersama penilaian dan perizinan, serta identitas bersama pengaturan dan dashboard.

## Pembaruan 18 November: privasi di komputer bersama (service worker dan draf lokal)

Dua cacat privasi yang ditemukan saat tinjauan akhir overhaul, keduanya sudah ada sebelum overhaul: data satu akun bisa sampai ke akun lain di browser yang sama. Dikerjakan di cabang `fix/web-shared-browser-privacy`, dipotong dari `claude/ui-overhaul-penyempurnaan-893ed6` di `c255538f`, lalu digabung ke cabang overhaul itu pada 18 November atas permintaan pemilik; cabangnya sendiri tidak di-push terpisah. Hanya `apps/web` yang berubah; API dan aplikasi mobile tidak disentuh. Perbaikan sesi yang bersebelahan (token klien setelah logout, cookie `sat`, mulai dan berhenti impersonasi) dikerjakan terpisah di cabang overhaul dan tidak diulang di sini.

### Yang ditemukan

**1. Service worker menyimpan data akun berdasarkan URL saja.** Dipastikan tanpa browser, dengan tiga cara:

- Daftar aturan produksi Serwist yang asli (`defaultCache` dari `@serwist/next/worker`, `NODE_ENV=production`) digabung persis seperti di `app/sw.ts` lama, lalu contoh permintaan dicocokkan dengan semantik rute Serwist. Hasilnya: `GET /v1/me` dengan bearer token masuk `NetworkFirst("others")`; API di origin lain masuk `NetworkFirst("cross-origin")`; navigasi ke halaman `(app)` masuk `NetworkFirst("pages")` dengan batas tunggu jaringan 10 detik; payload RSC masuk `pages-rsc` dan `pages-rsc-prefetch`; URL objek presigned se-origin masuk `others`.
- Worker hasil build produksi cabang overhaul (`public/sw.js` dari `c255538f`) memuat aturan yang sama.
- `cacheOnNavigation: true` membuat halaman (lewat web worker, bukan service worker) mengambil setiap tujuan navigasi dengan cookie lalu menyimpan HTML-nya ke cache `pages`. HTML `(app)` dan `(kiosk)` memuat hasil `GET /v1/me` milik pemegang cookie `sat`. API tidak mengirim `Vary: Authorization`, jadi pencocokan cache hanya berdasarkan URL: permintaan akun B cocok dengan entri akun A. Karena batas tunggu 10 detik itu, koneksi lambat saja sudah cukup; jaringan tidak harus mati.

Alur lengkapnya (dua akun bergantian di build produksi, lalu jaringan diputus) belum direproduksi di browser.

**2. Draf lokal hanya berkunci rekaman.** Dibaca langsung di kode: kelima modul draf (presensi, konseling, jurnal, buku nilai, observasi supervisi) menyimpan ke `localStorage` dengan kunci dari rekamannya saja, misalnya `newsekolah:counseling-draft:new`. Tidak ada tenant, tidak ada user, tidak ada yang menghapusnya saat logout, dan isinya tidak mencatat penulisnya. Form menawarkan apa pun yang ditemukan kepada siapa pun yang membuka rekaman yang sama.

**3. Halaman offline tidak pernah bisa tampil.** `/offline` tidak ada di daftar precache (194 entri: berkas `/_next/static/*` dan satu skrip worker navigasi), padahal `fallbacks` Serwist mengambilnya dari precache. Navigasi yang gagal selama ini menampilkan halaman galat bawaan browser, kecuali URL-nya kebetulan ada di cache `pages`.

### Yang diubah

Service worker (`app/sw.ts`, `lib/pwa/`, `next.config.ts`), dengan prinsip tolak secara bawaan:

- Hanya dua rute. Navigasi selalu ke jaringan (`NetworkOnly`, tanpa batas tunggu) dan tidak disimpan; bila jaringan gagal, halaman `/offline` dari precache yang tampil. Berkas build se-origin di `/_next/static/*` disajikan `CacheFirst` dari satu cache, `next-static-assets`. Permintaan lain (API `/v1/*`, `/ws/*`, payload RSC, penyimpanan objek, origin lain, route handler) tidak cocok dengan rute mana pun, jadi worker tidak menjawabnya sama sekali.
- `defaultCache` tidak dipakai lagi. Aturan lama menyaring daftar itu dengan daftar larangan, dan aturan yang tidak dilarang itulah yang bocor.
- `cacheOnNavigation` dimatikan.
- `/offline` masuk precache bersama tujuh chunk rute yang dimuat dokumennya, supaya tombol "Coba lagi" tetap berfungsi tanpa jaringan.
- Saat worker baru aktif, semua cache selain precache dan `next-static-assets` dihapus, begitu juga catatan URL milik plugin kedaluwarsa Serwist di IndexedDB (`serwist-expiration`), yang menyimpan path API beserta id rekaman.
- Halaman juga menghapus cache yang sama setiap kali identitas sesi mantap atau berganti dan saat logout, untuk menutup masa ketika worker lama masih mengendalikan tab yang terbuka. `skipWaiting` tetap `false` dan strip "pembaruan tersedia" tidak berubah.

Pilihan lain yang ditolak: nama cache per user (worker tidak tahu akun tanpa kanal pesan yang berpacu dengan permintaan dan hilang saat worker dimulai ulang, dan entrinya tetap tersimpan di disk bersama) dan sekadar menghapus cache saat login atau logout (menyisakan jeda antara penulisan dan penghapusan berikutnya).

Draf lokal (`lib/drafts/`, lima modul draf, lima form, `lib/session/`):

- Pemilik draf adalah tenant dan user, ditambah id admin yang sedang bertindak saat impersonasi atau role testing. Kunci baru: `newsekolah:draft:<pemilik>:<jenis>:<rekaman>`. Pemilik juga ditulis di dalam isi draf dan diperiksa lagi saat dibaca.
- Draf hanya ditawarkan kepada pemiliknya. Tanpa pemilik (sesi belum termuat atau anonim) tidak ada yang ditulis atau dibaca. Bila akun berganti saat form masih terbuka (misalnya tab lain login sebagai orang lain), form itu berhenti menyimpan draf sampai ditutup.
- Draf tetap bertahan melewati muat ulang, tab tertutup, koneksi putus, dan sesi yang kedaluwarsa, hanya untuk pemiliknya.
- Logout eksplisit (menu akun, layar wajib ganti password) menghapus semua draf di browser itu, milik siapa pun. Penghapusan dilakukan sebelum permintaan logout dikirim, jadi tetap terjadi walau jaringan gagal.
- Hentikan impersonasi bergantung pada hasilnya. Bila server mengembalikan sesi admin, hanya draf milik sesi impersonasi (pemilik `<tenant>:<user>~<admin>`) dan cache akun yang dihapus; draf admin sendiri tetap ada karena admin masih login di browser itu. Bila tidak ada sesi yang dikembalikan atau impersonasi sudah berakhir, itu logout eksplisit dan semua draf dihapus. Penghentian yang gagal tidak menghapus apa pun, karena impersonasi masih berjalan.
- Draf dengan kunci lama tidak bisa dikaitkan ke siapa pun, jadi dihapus sekali saat aplikasi dibuka. Akibatnya, draf yang belum tersimpan pada saat rilis hilang satu kali.
- Tidak ada penghapusan yang dipicu oleh `me` yang teramati, karena nilainya bisa tertinggal sesaat ketika identitas berganti.

Yang sengaja dibiarkan: di browser yang penggunanya tidak pernah logout secara eksplisit, draf akun yang sesinya kedaluwarsa tetap ada di `localStorage`. Draf itu tidak pernah ditawarkan kepada akun lain di aplikasi.

### Perilaku offline yang tersisa

- Halaman yang sedang terbuka tetap bekerja dari memori. Isian di lima form berdraf tersimpan lokal, realtime menyambung ulang dan menyelaraskan data saat koneksi kembali, dan `reloadOnOnline` memuat ulang halaman lalu menawarkan drafnya kembali.
- Membuka atau memuat ulang halaman apa pun saat offline menampilkan halaman offline aplikasi dengan tombol coba lagi. Ini baru sekarang benar-benar berfungsi.
- Halaman yang pernah dikunjungi tidak lagi dibuka dari cache saat offline, termasuk halaman publik (login, OPAC). Itu harga dari perbaikan ini.
- Logo sekolah di halaman offline hanya tampil bila cache HTTP browser masih menyimpannya; worker tidak lagi menyimpan gambar di luar `/_next/static/*`.
- Berkas build, strip pembaruan, dan push notification tidak berubah.

### Verifikasi sejauh ini

## Pembaruan 19 November (lanjutan): supervisi milik guru

Keputusan yang tadinya menunggu pemilik produk (guru mendapat 403 di "Supervisi saya") diambil: guru membaca hasil supervisinya sendiri dan menanggapinya, tanpa pernah melihat hasil guru lain.

- **Izin baru `view_own_supervision`** (`authz/permissions_supervision.go`). Peran bawaan Guru kini memegangnya bersama `respond_to_supervision` (sebelumnya tidak dimiliki peran bawaan mana pun). Migrasi `0128_teacher_own_supervision` membackfill keduanya ke peran sistem Guru di tenant yang sudah ada. `view_supervision` tetap tidak diberikan ke guru.
- **`x-permission` bisa berupa daftar alternatif.** `authz.LoadOperationPermissions` dan `authz.Authorize` menerima `x-permission: [view_supervision, view_own_supervision]`; cukup salah satunya, dan kunci API harus memegang alternatif yang sama. Daftar kosong, entri kosong, atau `authenticated` di dalam daftar menggagalkan startup. Enam operasi baca supervisi memakainya: daftar dan detail siklus, rencana kunjungan per guru, detail observasi, laporan per guru, dan ekspornya.
- **Cakupan ditegakkan di service.** Handler supervisi menurunkan `domain.Reader` dari izin pemanggil (`view_supervision` berarti semua guru); `TeacherReport`, `ExportTeacherReport`, `ListScheduledForTeacher`, dan `GetObservation` menolak id guru lain dengan 403 `SUPERVISION_OBSERVATION_FORBIDDEN` bagi pemegang izin sendiri saja. Sekalian diperbaiki: nama pengamat di ekspor laporan kini dibaca di dalam transaksi tenant; sebelumnya RLS menyembunyikan barisnya sehingga ekspor laporan yang punya observasi gagal.
- **Web**: `RouteGuard` mendapat `anyPermission`; "Supervisi saya" dan detail observasi, entri navigasinya, dan tab ruang kerja supervisi menerima salah satu izin. Tab "Siklus supervisi" tetap hanya untuk `view_supervision`, dan jejak detail observasi bagi guru kembali ke "Supervisi saya". Kepala sekolah yang belum punya siklus kini diarahkan ke tab siklus, bukan diminta menunggu pimpinan sekolah.
- **Uji**: unit `authz` (daftar alternatif, kunci API), integrasi `authz` dengan spec asli (guru lolos keenam operasi baca dan tanggapan, ditolak di daftar sekolah dan semua aksi pengamat; migrasi 0128 idempoten dan tidak menyentuh peran kustom), integrasi supervisi (laporan, ekspor, rencana kunjungan, dan observasi sendiri terbaca, milik guru lain ditolak).

Uji waktu memakai fitur simulasi waktu milik sistem (header `X-Simulation-Time`, hanya untuk pemegang `platform_superadmin`), bukan menunggu jam berjalan. Penguji memajukan jam per 15 menit, per jam, atau per hari sambil menyamar sebagai pustakawan, guru, dan siswa.

Pola bug terbesar: tanggal kalender dihitung dari tanggal UTC, bukan tanggal lokal sekolah. Di Asia/Makassar (UTC+8), apa pun sebelum pukul 08.00 WITA jatuh ke hari sebelumnya. Contohnya: jatuh tempo pinjaman maju sehari, perpanjangan di hari jatuh tempo ditolak, kunjungan perpustakaan tercatat di hari sebelumnya, dan batas simpan presensi baru tutup pukul 08.00 keesokan harinya. Putaran perbaikan waktu menyertakan penyisiran khusus atas pola ini di semua modul API, dan setiap kasus diuji dengan jam dibekukan di 23.30 UTC.

Penggabungan 11 cabang perbaikan menimbulkan konflik di presensi, notifikasi, analitik, impor perpustakaan, dan mesin PDF. Konflik diselesaikan dengan mempertahankan maksud kedua sisi. Migrasi yang bertabrakan dinomori ulang menjadi 0129-0139. Validasi di `0a56804`:

- `go build`, `go vet`, dan `go test ./...` dengan integrasi Postgres: 86 paket lulus.
- `pnpm typecheck`, `pnpm lint`, dan `pnpm test` lulus: web 495 berkas dan 2.977 uji, ui 790, mobile 133.

Catatan lingkungan lokal:

- Unggahan memakai server S3 tiruan (moto) di port 9000, karena MinIO tidak tersedia di kontainer.
- Akun `operator` (peran Super Admin, kata sandi sama dengan akun seed) hanya dibuat di basis data uji lokal untuk simulasi waktu. Akun ini bukan bagian dari seed.

## Yang tersisa

Diurutkan dari yang paling berdampak bagi pengguna.

### 1. Uji di browser

Setiap layar baru sudah dibuka sekali dan hasilnya tercatat di bagian "Yang terverifikasi". Yang belum dicoba adalah alurnya sampai tuntas, dengan data dan peran yang tepat:

- Perpustakaan: anggota, denda, import koleksi, label batch, kunjungan dan kiosk, lookup ISBN, ekspor.
- Kesiswaan: kandidat surat peringatan, pencatatan pelanggaran banyak sekaligus, lampiran dan topik konseling, laporan PDF siswa.
- Perizinan dan penilaian: antrean izin keluar, pemetaan TP, penyunting rentang nilai, rincian bintang siswa.
- Identitas: dashboard admin, import user, pengaturan sesi, branding dan logo, profil.
- Presensi: popover pelanggaran per sesi, rincian laporan harian, roster wali kelas, detail kalender siswa.

Uji ini butuh akun dengan peran wali kelas, guru BK, pustakawan, dan admin. Data demo perpustakaan (anggota, katalog, peminjaman, kunjungan) kini tersedia lewat `cmd/seed`; modul lain masih menyediakan sebagian, jadi siapkan penugasan tugas tambahan lebih dulu.

Satu hal yang paling perlu dibuktikan di browser: pembacaan berkas XLSX untuk import koleksi dan import user berjalan di sisi klien memakai `exceljs`, dan itu belum pernah dijalankan sungguhan.

### 3. Risiko terbuka

- ~~**Repo belum punya remote git.**~~ Sudah ada `origin` di GitHub (`omanjaya/newsekolah`).
- **Deploy VPS berikutnya butuh langkah manual.** Kode sudah memakai `app_rw` dan `compose.vps.yml`, tetapi `.env` di VPS harus diisi `APP_DB_PASSWORD` (migrate menolak jalan tanpanya), `DATA_ENCRYPTION_KEY`, dan `TRUSTED_PROXIES=127.0.0.1/32`, lalu `update.sh` dijalankan dengan `COMPOSE_EXTRA_FILES=infra/docker/compose.vps.yml`. Rincian di [audit pra-deploy](analysis/audit-pra-deploy-2026-09-23.md) dan `infra/README.md`.
- ~~**Aksen tenant tidak mengikuti mode gelap.**~~ Sudah diperbaiki. `TenantProvider` kini menulis dua variabel, `--tenant-accent` dan `--tenant-accent-dark`; yang kedua diturunkan oleh `apps/web/lib/tenant/accent.ts` dengan menaikkan lightness sampai menembus 4,5:1 di atas permukaan gelap `#1C1C1C`, sambil menahan saturasi agar tidak menyala. `app/globals.css` memilih salah satunya per tema. Aksen bawaan `#1F3A5F` naik dari 1,48:1 menjadi 4,68:1 (turunannya `#6288BC`). Uji ada di `accent.test.ts`; kaskadenya diverifikasi di browser untuk tiga jalur: sistem terang, sistem gelap, dan `data-theme="dark"` eksplisit.

## Cara memeriksa ulang

Menjalankan migrasi dan seed terhadap Postgres sekali pakai:

```bash
docker run -d --name nsk-check -e POSTGRES_PASSWORD=pw -e POSTGRES_DB=newsekolah -p 55433:5432 postgres:17-alpine
```

```bash
cd apps/api && DATABASE_URL='postgres://postgres:pw@localhost:55433/newsekolah?sslmode=disable' JWT_SIGNING_KEY="$(openssl rand -hex 32)" DOCUMENT_SIGNING_KEY="$(openssl rand -hex 32)" SEED_DEMO=true go run ./cmd/migrate up && go run ./cmd/seed
```

Mencari kemampuan API yang belum punya layar:

```bash
pnpm api:coverage
```

Test penuh, termasuk test integrasi. Butuh Docker aktif, dan jangan pakai `-short`:

```bash
cd apps/api && go test ./...
```

Data demo hanya membuat jadwal Senin sampai Jumat. Layar presensi yang kosong di hari Sabtu atau Minggu adalah perilaku yang benar.
