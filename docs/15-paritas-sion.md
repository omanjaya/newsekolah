# 15. Paritas dengan SION

Catatan kerja untuk menyamakan logika bisnis newsekolah dengan SION, aplikasi asal yang kodenya ada di `reference/sion-rebuild-go`. Dokumen ini menjawab satu pertanyaan: sampai mana pekerjaan ini, dan apa yang tersisa. Perbarui setiap kali ada bagian yang selesai.

Posisi terakhir: 25 September 2026 (dua item ledger perpustakaan: barcode kartu anggota, cetak kartu massal). **Barcode gambar pada kartu anggota**: `library/service/print.go`'s `PrintMemberCard` sebelumnya lewat `documents.Renderer` (perender HTML->PDF berbasis teks polos, membuang tag `<img>` -- lihat komentar paket) sehingga nomor anggota cuma tercetak sebagai teks; sekarang merender langsung dengan `fpdf`, memakai layout kartu ATM 85,6x54mm (`domain/cards.go`'s `CardPosition`, 2 kolom x 5 baris per A4, dari aplikasi lama `library_cards.go`) dan Code 128 gambar nomor anggota lewat `generateCode128PNG` yang sama dipakai label eksemplar (`service/labels.go`) -- satu jalur kode barcode untuk keduanya. Surat keterangan bebas pustaka tidak disentuh (tetap lewat `documents.Renderer`, tidak butuh barcode). **Cetak kartu anggota massal**: endpoint baru `POST /v1/library/members/cards` (`printLibraryMemberCards`, permission `manage_library_members`, `openapi/modules/library.yaml`) mencetak sampai 500 kartu (`domain.CardMaxPerPrint`) dalam satu PDF, dipilih lewat tepat satu dari tiga mode -- daftar `member_ids` eksplisit (urutan dipertahankan, query `GetMembersByIDs` baru), `member_type_id`, dan/atau `class_id` (keanggotaan aktif lewat `enrollments`, query `ListMembersForCardPrint` baru, keduanya bisa digabung). Layar Anggota (`members-view.tsx`) mendapat kolom pilihan baris (`selectionColumn`, pola sama `copies-browser-view.tsx`) plus bilah cetak `MemberCardPrintBar` untuk baris terpilih, dan tombol "cetak sesuai filter jenis" saat filter jenis anggota aktif. Diuji integrasi Postgres asli (`member_cards_integration_test.go`): tiga mode seleksi, gabungan tipe+kelas, penolakan kombinasi tidak sah (tanpa seleksi, id dicampur filter, id melebihi 500), filter tanpa hasil (404), dan paginasi lewat 10 kartu per halaman; test kedua membuktikan barcode sungguhan tertanam (marker `/Subtype /Image` pada PDF, bukan lagi kartu berbasis teks murni). Tidak ada migrasi (query baru memakai tabel `library_members`/`enrollments` yang sudah ada). `go test ./...` penuh (real Postgres via testcontainers), `pnpm typecheck && pnpm lint && pnpm test`, dan `check-migrations.sh` lulus.

Posisi sebelumnya: 24 September 2026 (sesi UI/UX penilaian guru). Merombak lembar nilai (`apps/web/features/grading`, komponen `gradebook-*`) memakai pola presensi guru sebagai referensi kualitas: navigasi keyboard spreadsheet penuh di desktop (panah kanan/kiri kini juga pindah kolom, bukan cuma naik/turun/Enter; Tab sudah bekerja gratis lewat urutan DOM), validasi rentang skala nilai inline per sel (`sheet.scale.min/max` yang sudah dikirim API, border merah plus pesan di bar simpan, tombol simpan kolom yang bersangkutan ikut nonaktif) tanpa perubahan API, dan tempel kolom dari Excel (`lib/gradebook-paste.ts`, mengisi blok sel mulai dari sel yang difokus, lintas siswa maupun lintas komponen). Sel yang berubah ditandai border aksen (`changed` di `GradebookScoreCell`, pola sama dengan titik "berubah" di baris presensi). Rata-rata kini dihitung ulang langsung dari edit yang belum tersimpan (`lib/gradebook-scores.ts`'s `computeLiveAverage`, meniru `WeightedAverage` Go persis) alih-alih menunggu simpan; nilai rapor yang belum sinkron dengan edit tertunda mendapat titik kecil "diperbarui setelah disimpan". Kolom komponen menampilkan jumlah siswa yang belum diisi nilainya. Badge "Draf"/"Diterbitkan" ditambah di samping saklar terbitkan. Ponsel mendapat dua mode isi nilai yang bisa ditukar: "Per komponen" (baru, default -- satu komponen dipilih lewat chip yang menampilkan sisa kosong, lalu daftar siswa dengan input besar berturut-turut, cocok untuk mengoreksi satu kuis untuk seluruh kelas) dan "Per siswa" (kartu lama, satu siswa dengan semua komponennya). Draf lokal (`lib/gradebook-draft.ts`, pola sama `attendance-draft.ts`) menyimpan edit yang belum tersimpan ke localStorage per lembar kelas-mapel-semester dan menawarkan pemulihan setelah reload; bar simpan bawah (`packages/ui`'s `StickySaveBar`, komponen baru yang diekstrak dari `session-save-bar.tsx` presensi supaya kedua fitur memakai implementasi yang sama) menampilkan jumlah perubahan tertunda dan tombol "Simpan semua" yang mengirim setiap kolom yang berubah berurutan, dengan toast sukses berwaktu dan tombol "Coba lagi" saat gagal. `grade-ranges-editor.tsx` tidak disentuh selain memastikan gayanya tetap konsisten. Tidak ada perubahan API/migrasi -- semua data yang dibutuhkan (skala nilai per sel) sudah ada di respons `Gradebook` yang ada.

Sesi paralel 24 September 2026 (UI/UX alur harian guru: jurnal, kelas binaan, guru pengganti, presensi kerja). Empat layar dirombak memakai kelas kualitas alur presensi guru (session-card, chip status, bar simpan, draf localStorage) sebagai acuan. **Jurnal mengajar** (`apps/web/features/journal`): panel baru "Pelajaran terakhir" di atas tabel riwayat menampilkan jadwal mingguan guru diekspansi jadi baris per hari sekolah 7 hari terakhir (`lib/build-lesson-days.ts`, murni dan diuji, dikombinasikan dengan `useSchedulesQuery`+`useSchoolDaysQuery` yang sudah ada -- tanpa endpoint baru) dengan indikator terisi/belum dan satu ketukan membuka form isi; tiga field jurnal (topik/kegiatan/refleksi) dipindah ke `JournalFields` yang kini dipakai bersama oleh form berdiri sendiri dan tab Jurnal di sesi presensi (`SessionJournalPanel`), sehingga dua pintu masuk berperilaku identik; draf localStorage per kelas/mapel/tanggal (`lib/journal-draft.ts`) dengan prompt pulihkan. **Kelas binaan** (`apps/web/features/homeroom`): halaman tadinya cuma tabel `DataTable` padat kini dashboard sekilas pandang -- kartu stat (total/alpha/belum lengkap/izin menunggu), tiga kartu "Perlu perhatian hari ini" (siswa alpha/belum lengkap, tombol telepon dan WhatsApp ke wali lewat `lib/guardian-contact.ts`), "Izin menunggu persetujuan" (`useLeaveReviewQueueQuery` yang sudah ada, disaring ke `class_id` kelas binaan lewat `duties[].scope_id`), dan "Catatan pelanggaran" (dari `violation_count`/`violation_points` yang sudah ada di `AttendanceHomeroomEntry`) -- tabel lengkap tetap ada di bawahnya untuk pencarian/filter. **Guru pengganti** (`apps/web/features/substitutions`): kartu daftar kini menampilkan kelas, mata pelajaran, dan jam pelajaran yang digantikan, bukan cuma tanggal dan nama guru -- API `Substitution` dapat empat field opsional baru (`class_id`/`subject_id`/`start_period_id`/`end_period_id`) diisi lewat query `sqlc.embed` baru yang join ke `schedules` (`ListSubstitutionsIncomingWithSchedule`/`ListSubstitutionsOutgoingWithSchedule`, aman di-join karena `schedule_id` cascade on delete), diuji integrasi Postgres asli; badge "Hari ini" pada permintaan tanggal berjalan. **Presensi kerja** (`apps/web/features/staff-attendance`, `self-check-in-view.tsx`): jam besar hidup, dan "hari ini"/"minggu ini" kini dari server lewat endpoint self-service baru `GET /v1/staff-attendance/me/history` (`x-permission: authenticated`, pola sama seperti `scanStaffAttendance` -- resolve user dari context, bukan path param) alih-alih tebakan `localStorage` yang sebelumnya jadi satu-satunya sumber karena endpoint riwayat lama mensyaratkan permission `view_staff_attendance` yang tidak dimiliki pegawai biasa; diuji integrasi Postgres asli (karyawan lain tidak bisa melihat riwayat ini, dan kode status terkomputasi benar untuk hari tanpa jadwal). Alur diverifikasi ujung-ke-ujung di aplikasi berjalan dengan akun `guru` (data sementara ditambah lewat SQL untuk kasus yang seed tidak sediakan -- guardian_phone, permintaan pengganti berisi -- lalu dihapus setelah screenshot).

Sesi paralel 24 September 2026 (UI/UX alur harian kesiswaan: izin, presensi piket, pelanggaran, konseling). Lima layar (`apps/web/features/permits`, `apps/web/features/discipline`) dirombak memakai kelas kualitas alur presensi guru sebagai acuan, tanpa perubahan API. **Izin terencana**: antrean wali kelas dan antrean orang tua (yang sebelumnya hanya membuka dialog detail untuk apa pun) kini punya baris dengan aksi "Setujui" satu ketuk dan "Tolak" lewat popover alasan kecil (`leave-queue-row.tsx`, dipakai kedua antrean), plus aksi massal "Setujui terpilih" dengan keterangan eksplisit "tidak menambahkan catatan" -- setiap item di kedua endpoint antrean sudah dijamin server berada di tahap milik pemanggil sendiri, jadi tidak perlu membuka detail dulu untuk tahu bisa diputuskan. Form pengajuan kini menangkap foto bukti opsional (input kamera) di layar yang sama, dirantai sebagai panggilan kedua ke `useUploadEvidenceMutation` setelah `submit` berhasil (gagal unggah tidak membatalkan pengajuan, hanya memberi peringatan) -- sebelumnya bukti hanya bisa dilampirkan di kunjungan kedua ke halaman detail. **Izin keluar dan terlambat**: panel setujui/gerbang piket dan langkah pindai tahap siswa sendiri kini memakai `BarcodeScannerField` bersama (pemindai kamera/keyboard-wedge/input manual yang sama dipakai meja sirkulasi perpustakaan) menggantikan `ScanTokenInput` yang dihapus; panel gerbang menyimpan daftar "baru saja keluar" per sesi browser dengan waktu dan aksi sembunyikan (bukan pembatalan sungguhan di server -- diberi label jujur "Sembunyikan dari daftar ini"); kedua antrean review dapat filter cari nama/NIS. **Pelanggaran**: form catat kini bisa memilih beberapa siswa sekaligus (cari + daftar centang, pola sama dengan pemilih jenis pelanggaran), memanggil mutation satu-siswa yang sudah ada berulang per siswa terpilih dan menampilkan ringkasan poin/ambang SP per siswa setelah simpan. **Konseling**: form catatan mendapat draf localStorage dengan prompt pulihkan (pola sama `attendance-draft.ts`, file baru `lib/counseling-draft.ts`). `format-name.ts` pindah dari `attendance/lib` ke `lib/text` karena kini dipakai permits dan discipline juga. Belum dikerjakan: bukti foto untuk catatan pelanggaran (belum ada endpoint unggah untuk pelanggaran, tidak seperti bukti izin dan lampiran konseling -- perlu penambahan API sungguhan, di luar cakupan sesi ini), pratinjau ambang SP langsung saat memilih jenis pelanggaran (perilaku ringkasan-setelah-simpan yang sudah ada dipertahankan), dan pencatatan izin keluar/terlambat oleh piket atas nama siswa tanpa permintaan QR dari siswa lebih dulu (alur saat ini selalu diinisiasi siswa; mencatat atas nama siswa butuh endpoint baru sisi staf). Diverifikasi ujung-ke-ujung dengan API dan web sendiri (port 8103/3103) memakai akun admin/guru/gurubk/siswa/ortu terhadap Postgres dev bersama; data sementara (satu pengajuan izin, satu izin keluar) dihapus setelah tangkapan layar, dan satu catatan izin lama yang macet di status "approved" walau suratnya sudah terbit diperbaiki jadi "completed" (bug pra-eksisting yang tidak dikejar lebih jauh: pengecekan "satu izin aktif" tampaknya menganggap "approved" selalu masih berjalan, tanpa melihat apakah surat sudah terbit).

Sesi paralel 24 September 2026 (UI/UX alur harian keuangan dan tamu: loket pembayaran, papan tamu, komposer pengumuman). Tiga layar (`apps/web/features/billing`, `apps/web/features/visitors`, `apps/web/features/announcements`) dirapikan memakai kelas kualitas alur presensi guru sebagai acuan, tanpa perubahan API. **Loket pembayaran** (`payment-desk-view.tsx`): pemilih siswa berganti dari `Select` polos (mesti digulir manual di antara ratusan siswa) ke `Combobox` yang menyaring direktori yang sudah termuat di klien saat diketik -- direktori kecil untuk sekolah tunggal sehingga penyaringan klien memadai, `PersonPicker` async penuh (disebut `docs/05-shared-components.md`) belum dibangun dan di luar cakupan sesi ini. Status tagihan kini punya empat keadaan yang jelas dibedakan warna lewat token status yang sama dengan presensi (`lib/bill-status.ts`, `BillStatusBadge` baru dipakai bersama loket/daftar tagihan/detail tagihan): Lunas (hijau), Dibayar sebagian (oranye), Jatuh tempo (merah, belum lunas dan lewat tanggal jatuh tempo), dan Belum dibayar polos (belum jatuh tempo, tidak butuh perhatian). Memilih siswa kini menampilkan ringkasan `StatGrid` (total tunggakan, jumlah tagihan) sebelum daftar kartu tagihan, dan kartu tagihan terurut berdasar urgensi (jatuh tempo, lalu sebagian, lalu belum dibayar, baru lunas paling akhir) alih-alih urutan API apa adanya. Tombol kwitansi kini mencoba Web Share API dulu (`lib/receipt.ts`) sebelum jatuh ke buka tab baru, sehingga di HP kwitansi bisa langsung dibagikan ke WhatsApp tanpa mencari tab. Konfirmasi pembatalan pembayaran (`VoidPaymentDialog`, sudah ada sebelum sesi ini) sudah mensyaratkan alasan dan tombol destruktif terpisah -- tidak diubah. **Papan tamu** (`gate-board-view.tsx`): kotak cari (muncul begitu tamu di kampus lebih dari tiga) menyaring nama/instansi di klien, karena papan ini sudah realtime tanpa server-side search. **Komposer pengumuman** (`announcement-form.tsx`): form kini dua tab, "Tulis" dan "Pratinjau" -- tab pratinjau merender judul, ikon sematkan bila diaktifkan, kapan tampil (segera atau terjadwal), penerima (memakai `describeAudience` baru yang diekstrak dari `announcements-manage.tsx` supaya kolom "Dibaca" di tabel kelola dan pratinjau komposer tidak pernah mendeskripsikan audiens secara berbeda), dan isi lewat `SafeHtml` yang sama dipakai umpan pembaca -- sebelum ini penulis tidak bisa tahu tampilan pengumumannya sebelum menerbitkan. Statistik baca ("Dibaca X dari Y") sudah ada di tabel kelola sebelum sesi ini, tidak diubah. Diverifikasi ujung-ke-ujung dengan API dan web sendiri (port 8103/3103) memakai pengguna sementara `w2c-admin` (dibuat lewat API dari akun admin bersama, diarsipkan lewat `POST /v1/users/{id}/archive` di akhir sesi karena API tidak punya hapus permanen) terhadap Postgres dev bersama; tiga tagihan dan dua pembayaran sementara (mendemonstrasikan keempat status tagihan untuk satu siswa) dan empat kunjungan tamu sementara (mendemonstrasikan papan terisi dan pencarian) dihapus dari database setelah tangkapan layar -- jumlah baris `bills`/`visitor_visits` diverifikasi kembali ke angka semula.
Sesi paralel 24 September 2026 (menutup tiga item "belum dikerjakan" dari sesi kesiswaan di atas, kontrak-dulu API + web, migrasi `0115_violation_attachments`). **Bukti foto pelanggaran**: `violation_attachments` (tenant_id, violation_record_id, asset_id) mengikuti pola persis `counseling_attachments` -- endpoint presigned upload-url/confirm/list/url baru di `openapi/modules/discipline.yaml` (`/v1/discipline/violations/{recordId}/attachments...`), `service.RequestViolationAttachmentUpload`/`ConfirmViolationAttachment` (re-encode JPEG/PNG untuk buang EXIF, batas 10 MB dan 3 foto per catatan, `ErrAttachmentLimitReached` baru) meniru `counseling.go` persis; Endpoint baru `POST /v1/exit-permits/staff-record` dan `POST /v1/late-arrivals/staff-record` (`x-permission: issue_scan_tokens`, permission meja piket yang sudah ada); tab baru "Catat manual" di `DutyView` (`duty-manual-record-panel.tsx`) dengan pencarian siswa, pilihan izin keluar/terlambat, dan field sesuai jenis. Posisi sebelumnya: 24 September 2026 (sesi UI/UX presensi guru). Merombak alur "guru mengisi presensi" (`apps/web/features/attendance`) untuk target < 30 detik/36 siswa di ponsel: daftar sesi hari ini kini terurut waktu dengan penanda "Sedang berlangsung"/"Berikutnya", progres isi (`roster_count`/`entered_count` baru di `AttendanceSessionSummary`, dihitung sekali per sesi dari `ListActiveEnrollments`/`ListEntriesBySession` yang sudah ada, tanpa query SQL baru), dan status "Belum diisi"/"Tersimpan pukul HH:MM"/"Terkunci"; desktop memakai layout dua kolom (daftar plus ringkasan hari). Ditelusuri di `reference/sion-rebuild-go/frontend/app/attendance/page.tsx`: tidak ada tombol "Centang H Semua" maupun kode status "PMT" (PMT hanya disebut di PRD sebagai modul LMS suspensi siswa yang terpisah, tidak pernah diimplementasikan di kode); tidak ada rekap A/I/S/D per siswa di kode lama (hanya "PS" -- status pertemuan sebelumnya, sekarang diadopsi sebagai catatan kecil di baris bila statusnya bukan hadir); tidak ada ambang batas alpha; tombol pelanggaran memakai warna primer, bukan oranye. ## Bagaimana pekerjaan ini berjalan

1. **Perbandingan.** Tiap aturan bisnis di handler SION dicari padanannya di kode baru dan diberi status per fitur. Hasil lengkapnya ada di [Lampiran D](analysis/parity-sion-before.md). 6. **Pembangunan layar** untuk kemampuan backend yang belum punya antarmuka, dalam tiga kelompok paralel: perpustakaan, kesiswaan bersama penilaian dan perizinan, serta identitas bersama pengaturan dan dashboard.

## Cara memeriksa ulang

Menjalankan migrasi dan seed terhadap Postgres sekali pakai:

```bash
docker run -d --name nsk-check -e POSTGRES_PASSWORD=pw -e POSTGRES_DB=newsekolah -p 55433:5432 postgres:17-alpine
```

```bash
cd apps/api && DATABASE_URL='postgres://postgres:pw@localhost:55433/newsekolah?sslmode=disable' JWT_SIGNING_KEY="$(openssl rand -hex 32)" DOCUMENT_SIGNING_KEY="$(openssl rand -hex 32)" SEED_DEMO=true go run ./cmd/migrate up && go run ./cmd/seed
```

Mencari kemampuan API yang belum punya layar:

```bash
pnpm api:coverage
```

Test penuh, termasuk test integrasi. Butuh Docker aktif, dan jangan pakai `-short`:

```bash
cd apps/api && go test ./...
```

Data demo hanya membuat jadwal Senin sampai Jumat. Layar presensi yang kosong di hari Sabtu atau Minggu adalah perilaku yang benar.
