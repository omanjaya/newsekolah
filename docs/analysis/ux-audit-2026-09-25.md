# Audit UX, 25 September 2026

Audit UX per peran terhadap aplikasi sungguhan (`pnpm dev:docker`, data seed `sma-contoh`), dijalankan dengan Playwright di viewport desktop 1440x900 dan HP 390x844 (iPhone 12). Sesi ini read-only terhadap kode aplikasi: satu-satunya keluaran adalah dokumen ini dan tangkapan layar di `docs/analysis/ux-audit-2026-09-25/`. Peran orang tua sengaja dilewati sesuai arahan (perannya sedang dihapus dari produk).

## Metodologi

- Skrip Playwright sekali pakai (tidak disertakan di repo) login sebagai tiap peran lewat form sungguhan, lalu membuka 4-6 layar tugas utama per peran di kedua viewport. Login memakai form UI nyata (bukan mock e2e `apps/web/e2e`), API dan Postgres sungguhan dari `pnpm dev:docker`.
- Akun seed dipakai apa adanya: `admin`, `guru`, `gurubk`, `siswa`. Akun `kepsek` ada di `apps/api/cmd/seed/main.go` tetapi tidak ada di database dev yang sedang berjalan (containers sudah aktif 5+ hari, sejak sebelum peran `principal` ditambahkan) -- `pnpm dev:docker:seed` dijalankan ulang untuk melengkapinya; perintah ini idempoten (mengecek username sebelum membuat), jadi aman dan tidak mengubah data lain. Akun `pustakawan` (peran Pustakawan) dan `staf` (peran Pegawai) dibuat lewat `POST /v1/users` sesuai arahan karena seed belum menyediakannya; keduanya mengalami alur "ubah kata sandi sebelum melanjutkan" pada login pertama seperti akun buatan admin sungguhan.
- **Rate limit login**: `LoginRateLimiter` (`apps/api/internal/platform/auth/ratelimit.go`) membatasi 5 percobaan/15 menit per akun dan 20/15 menit per IP. Pengujian awal sempat kena limit sendiri (banyak percobaan login berurutan dari IP container yang sama); kunci Redis `login:*` dibersihkan manual dua kali untuk melanjutkan pengujian -- ini murni state Redis dev, bukan perubahan kode atau data aplikasi. Perilaku limit itu sendiri relevan dan dicatat sebagai temuan (lihat tabel).
- **Artefak tangkapan layar**: semua tangkapan mobile memakai `fullPage: true`. Tab bar bawah memakai `position: fixed` (`components/mobile-tab-bar.tsx`), sehingga pada tangkapan _full-page_ yang di-stitch, tab bar tampak "membeku" di tengah gambar alih-alih di bagian bawah -- ini murni artefak cara Playwright men-screenshot elemen fixed pada halaman panjang, **bukan bug render sungguhan** (diverifikasi ulang dengan tangkapan viewport-saja sambil men-scroll sungguhan: tab bar tetap menempel benar di bawah, lihat `admin-mobile-tabbar-verify.png`).
- **Performa di dev**: waktu muat di bawah diukur dari `page.goto` sampai `networkidle` pada server dev Next.js (bukan build produksi), jadi memuat sebuah rute untuk pertama kali termasuk waktu kompilasi on-demand Next -- ini melambungkan angka jauh di atas apa yang akan dialami pengguna produksi. Angka dipakai untuk membandingkan layar secara relatif (mana yang lebih berat), bukan sebagai SLA.
- Bahasa (copy Indonesia, Title Case vs sentence case, sisa teks Inggris) diperiksa visual pada setiap tangkapan: tidak ditemukan sisa teks Inggris atau ketidakkonsistenan kapitalisasi pada label, tombol, atau pesan yang diuji. Kontras warna dan struktur ARIA tidak diukur otomatis (tidak ada axe run pada sesi ini) -- sampling visual tidak menemukan pelanggaran mencolok, tetap disarankan menjalankan axe di CI sesuai `docs/07-ui-ux.md` bagian 6.
- Data yang tampil di beberapa layar (mis. banyak baris "Siswa Contoh" / "smoke test" di Pelanggaran, dan puluhan pinjaman perpustakaan atas nama siswa acak) berasal dari sesi pengujian sebelumnya di database dev yang sama, bukan dari sesi ini -- disebut di tabel hanya bila memengaruhi penilaian UX (mis. volume baris pada mobile), bukan sebagai bug aplikasi.

## Kemenangan cepat (quick wins)

1. Sembunyikan kartu "Denda belum dibayar" saat Rp0 dan hapus kalimat "cari judul untuk memesan" saat reservasi mandiri nonaktif -- dua perbaikan copy/kondisional kecil di satu komponen (`/library/me`).
2. **Selesai.** Tambahkan `profileKinds: ["teacher", "staff"]` ke item nav "Kelas binaan" -- satu baris di `navigation.ts`, menutup kebocoran IA yang paling jelas di audit ini.
3. Bungkus badge + switch "Terbitkan ke siswa" pada `gradebook-sheet.tsx` dengan `{canManage && (...)}` -- konsisten dengan pola yang sudah dipakai untuk kontrol lain di file yang sama.
4. Jangan render status kalender presensi untuk tanggal setelah hari ini.
5. Samakan branding header login mobile dengan panel hero desktop (nama/logo tenant, bukan nama produk platform).

## Catatan operasional (bukan temuan UX, tapi ditemukan selama audit)

- Akun `kepsek` yang didokumentasikan di `docs/analysis/audit-pra-deploy-2026-09-23.md` sebagai tersedia "hanya lokal" ternyata tidak ada di database dev yang sudah berjalan lama; `pnpm dev:docker:seed` perlu dijalankan ulang (aman, idempoten) setiap kali database dev lama dipakai kembali setelah fitur baru menambah baris seed. Pertimbangkan mencatat langkah ini di `infra/docker/README.dev.md` sebagai pengingat "re-run seed after pulling new seed accounts".
