# Audit pra-deploy VPS, 23 September 2026

Audit statis sebelum branch `fix/schedule-grid-alignment` dipublikasikan ke VPS untuk uji menyeluruh. Empat pemeriksaan paralel (keamanan backend, keamanan web dan infra, sidebar dan RBAC per peran, kelengkapan fitur) dijalankan read-only tanpa build, test, atau perubahan kode. Setiap temuan berat diverifikasi ulang langsung ke berkas yang dirujuk. Tidak ada kode yang diubah di sesi ini; dokumen ini adalah satu-satunya keluaran.

## Ringkasan

Fondasinya kuat: Argon2id, JWT ES256 dengan rotasi refresh dan deteksi reuse, setiap operasi OpenAPI wajib `x-permission` (gagal start bila tidak), scope objek di service (BK, wali kelas, orang tua-anak, guru mapel), RLS lengkap di 137 dari 138 tabel, tidak ada SQL yang dirangkai string, upload privat dengan sniffing dan strip EXIF, CSP ber-nonce di web, token akses hanya di memori, dan tidak ada port database yang dipublikasikan di compose produksi. Sidebar dibangun dari satu registry yang juga menjadi guard rute, sehingga URL yang diketik langsung tetap diblokir dengan halaman "tidak punya akses", bukan sekadar menu disembunyikan. Tidak ada tautan sidebar yang mati, tidak ada halaman yatim, tidak ada tombol tanpa fungsi, dan hanya satu kunci i18n yang rusak dari 3.682 pemanggilan.

Yang harus dibereskan sebelum uji di VPS ada di tiga kelompok. Pertama, konfigurasi deploy: API tersambung ke Postgres sebagai superuser sehingga RLS tidak pernah aktif, dan file override VPS yang mem-publish port 3011/8081 tidak ada di repo sehingga `update.sh` akan menjalankan compose tanpa port itu. Kedua, otorisasi: peran "Admin Sekolah" bawaan ikut menerima izin konsol platform lintas-tenant, dan pencabutan sesi tunggal tidak membersihkan cache sesi. Ketiga, dua bug kecil yang pasti ketemu penguji: tombol penyelesaian pelanggaran perpustakaan memanggil kunci terjemahan yang berupa objek, dan kunci publik VAPID tidak sampai ke bundle web di compose produksi.

## Sidebar per peran

Tujuh peran sistem di-seed per tenant (`super_admin`, `admin`, `teacher`, `staff`, `student`, `parent`, `librarian`) dan enam duty (`homeroom`, `counselor`, `picket`, `leadership`, `security`, `librarian`) yang izinnya digabung ke izin efektif pengguna. Peran bisa dikustomisasi penuh per tenant di `/settings/roles`, jadi matriks di bawah adalah kondisi bawaan. Angka adalah item yang terlihat dari total item grup, tidak menghitung item `sidebarPlacement: "hidden"` (profil, notifikasi, keamanan, tampilan -- dijangkau dari menu akun, bukan daftar sidebar).

**Diperbarui 25 September 2026** setelah sesi navigasi (`apps/web/lib/navigation.ts`, `navigation-academic.ts`) memberi `leave-requests`, `exit-permits`, `late-arrivals`, `school-classes`, dan `academic-years` izin yang mencerminkan layar sungguhan di baliknya (lihat commit "fix(web): scope permission-free sidebar items to the roles that use them"). Angka Akademik, Kepegawaian, dan Perpustakaan juga bergeser dari versi 23 September karena modul lain (kehadiran staf, ekstrakurikuler, mentoring) menambah item sejak itu -- pergeseran itu bukan bagian dari sesi ini.

Catatan yang perlu diputuskan pemilik produk:

- **Selesai**: pustakawan tidak lagi melihat "Jurnal kelas" (0 item Akademik, dulu 1) -- `journal` sudah dibatasi ke `profileKinds: ["teacher", "staff"]` plus `view_academic_data` di sesi sebelumnya.
- **Selesai**: siswa dan orang tua tidak lagi melihat "Kelas dan siswa" maupun "Tahun ajaran" di Data sekolah (0, dulu 2 untuk siswa) -- keduanya sekarang mengecualikan profil `student` dan `parent` lewat `excludeProfileKinds` walau tetap memakai `view_academic_data`, jadi guru, staf, dan admin/super admin (termasuk yang tidak punya baris profil sama sekali, seperti akun bootstrap) tidak kehilangan akses.

## Perbaikan dan verifikasi RLS di bawah `app_rw`

Setelah API dipindah dari superuser ke `app_rw`, RLS benar-benar berlaku untuk pertama kalinya, dan itu membuka tiga kelas bug yang selama ini tersembunyi karena superuser melewati semua policy:

1. **GUC kosong memicu 22P02.** Setelah satu koneksi pool pernah menjalankan `SET LOCAL app.tenant_id`, placeholder GUC kembali ke `''`, bukan NULL. Cast `::uuid` di 137 policy `tenant_isolation` lalu gagal untuk setiap query di luar transaksi tenant pada koneksi itu. Diperbaiki di migrasi 0110 dengan `nullif`.
2. **Fungsi DDL tanpa hak.** `ensure_notifications_partition` menjalankan `CREATE TABLE`, yang tidak dimiliki `app_rw`. Diperbaiki di migrasi 0111 dengan `SECURITY DEFINER` dan `search_path` terkunci.
3. **Use case di luar transaksi tenant.** Repository jatuh ke pool mentah bila tidak ada transaksi, sehingga query RLS mengembalikan nol baris tanpa error. Pemindaian statis menemukan 96 method service publik yang terdampak, sekitar 75 di perpustakaan. Terbukti langsung: `/v1/library/locations` dan `/v1/library/members` mengembalikan `[]` padahal ada data. Semua dibungkus `withTx`.

Verifikasi dengan API yang berjalan sebagai `app_rw` terhadap Postgres berisi data seed: login dan `/v1/me`, semua endpoint GET perpustakaan tanpa parameter path (jumlah baris cocok dengan isi tabel), pemindaian semua endpoint GET lain tanpa 500, penulisan lokasi perpustakaan, serta permintaan reset password yang menulis baris reset dan audit log. Test integrasi kini berjalan sebagai role non-superuser agar kelas bug ini tertangkap otomatis.
